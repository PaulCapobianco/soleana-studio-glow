# Audit Soleana Studio — octobre 2026

**Date :** 27 septembre 2026
**Méthode :** analyse uniquement — aucune modification de code, aucun commit hors celui-ci, aucune écriture en base, aucun déploiement. Travail effectué sur un worktree dédié (`audit-2026-10`, créé depuis `main`, tip `cfda0d3`) et sur le site en production `https://soleanastudio.fr` (lecture seule : `curl`, Lighthouse local, en-têtes HTTP).
**Périmètre :** sécurité, référencement (SEO), qualité de code, RGPD, plus un lot séparé sur les restes du scaffolding Lovable.

## Comment lire ce rapport

Pour chaque constat, un statut de branche est donné :
- **ouvert partout** — le problème existe sur `main` (donc en production, une fois le point 0 réglé) et n'est corrigé sur aucune des branches non fusionnées.
- **corrigé sur `apres-noel`** / **corrigé sur `perf-mobile`** — déjà réglé sur cette branche, avec le commit exact ; se réglera à la fusion, **ne pas replanifier**.
- **prévu sur `photos-storage`** — préparé ou documenté sur cette branche, en attente de son propre chantier.

`apres-noel`, `perf-mobile` et `photos-storage` sont poussées mais pas fusionnées dans `main`. Elles partagent une bonne partie de leur historique (`perf-mobile` a divergé d'`apres-noel` après ses correctifs de sécurité admin ; `photos-storage` a fusionné `apres-noel` en cours de route) : un correctif « sur `apres-noel` » est donc, sauf mention contraire, également présent sur les deux autres. **Le plan d'action (section 8) ne retient que les constats « ouvert partout ».** L'ordre de fusion déjà arrêté est rappelé en section 9.

## 0. Priorité absolue : la production ne fait pas tourner `main`

**Gravité : critique.** Preuve indépendamment vérifiée : le `sitemap.xml` servi par `https://soleanastudio.fr` est identique, URL pour URL, à celui du commit `f4dd25b` (25/09/2026), alors que `main` en est aujourd'hui à `cfda0d3` (26/09/2026) — **41 commits d'écart**. Confirmé aussi sur `/mini-seances-noel-2026` (404 en prod alors que la route existe sur `main`) et sur `/og-image.jpg` (404 en prod, confirmé par `curl`).

Conséquence concrète : plusieurs correctifs déjà écrits, testés et fusionnés dans `main` sont invisibles en production tant qu'un redéploiement n'a pas lieu :

| Déjà corrigé sur `main`, non déployé | Preuve en production |
|---|---|
| `/faq` : les questions/réponses sont chargées côté client (React Query) au lieu d'un `loader` SSR → la page est vide pour un moteur qui ne rend pas le JS | `curl https://soleanastudio.fr/faq` → `<div class="space-y-2" data-orientation="vertical"></div>` (accordéon vide, aucune question dans le HTML) |
| `/prestations` : grille de tarifs non servie côté serveur | Contenu Supabase (`services`) absent du HTML brut |
| `og:image` absent sur toutes les pages sauf l'accueil | Vérifié page par page |
| JSON-LD `ProfessionalService.image` pointe vers une image qui n'existe pas | `curl -o /dev/null -w "%{http_code}" https://soleanastudio.fr/og-image.jpg` → `404` |
| `/mini-seances-noel-2026` répond 404 | Route absente de la prod, présente sur `main` (`24e002e`) |
| Le clic-pour-charger sur les iframes Pelli (`ConsentEmbed`) n'est pas actif | Les 3 iframes (`/contact`, `/reservation`, `/espace-client`) se chargent sans condition en prod (voir RGPD-01, section 4) |

**Action : redéployer `main` (`npm run build && wrangler deploy`, ou le flux en place), à l'initiative de Paul.** Aucune ligne de code n'est nécessaire pour ces six points — c'est l'action isolée à plus fort effet de tout cet audit. Elle ne figure pas dans le plan d'action par lots (section 8) car ce n'est pas un chantier de code : c'est un déploiement.
